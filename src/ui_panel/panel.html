Remove a file from git history

This rewrites history: every commit hash from the first commit containing the file onwards changes, and you will have to force-push. Agree with your team first.

0. Back up

Push or stash any pending work, then make a safety copy of the repository.

git clone --mirror <repo-url> repo-backup.git

1. Rewrite history — git filter-repo (recommended)

Fast and safe; officially recommended by git. Requires Python.

pip install git-filter-repo

Remove a single file (path relative to the repo root):

git filter-repo --invert-paths --path path/to/file

Remove a folder, or every file matching a pattern:

git filter-repo --invert-paths --path path/to/folder/
git filter-repo --invert-paths --path-glob '*.pfx'

If it refuses because the repo is not a fresh clone, add --force (you made a backup).
filter-repo removes the origin remote on purpose; add it back:

git remote add origin <repo-url>

1-bis. Alternative — git filter-branch (built-in, slower)

No install needed. Works in both PowerShell and bash.

git filter-branch --force --index-filter "git rm --cached --ignore-unmatch path/to/file" --prune-empty --tag-name-filter cat -- --all

Then drop the backup refs and the old objects:

git for-each-ref --format="delete %(refname)" refs/original | git update-ref --stdin
git reflog expire --expire=now --all
git gc --prune=now --aggressive

2. Verify

Should print nothing:

git log --all --oneline -- path/to/file

3. Stop it from coming back

If the file still exists on disk, add it to .gitignore and commit.

git add .gitignore
git commit -m "ignore path/to/file"

4. Force-push every branch and tag

git push origin --force --all
git push origin --force --tags

Protected branches must be temporarily unprotected on the server (GitHub / GitLab / Azure DevOps).

5. Afterwards

  • Every collaborator must re-clone (or git fetch + git reset --hard origin/<branch_name>). An old clone that pushes will bring the file back.
  • Forks, open pull requests and server caches can still hold the file — on GitHub/GitLab ask support to run garbage collection if it must really disappear.
  • If the file contained passwords, keys or tokens: rotate them. Once pushed, consider them leaked, regardless of the rewrite.

Only stop tracking it (no history rewrite)

Removes the file from the next commit but keeps it on disk; older commits still contain it.

git rm --cached path/to/file
